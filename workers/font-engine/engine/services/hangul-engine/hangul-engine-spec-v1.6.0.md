# 한글 대표 음절·위치형 엔진 기술 명세 v1.6.0

## 1. 목적

한글 대표 음절 168자를 TrueType 글리프로 빌드할 수 있는 입력으로 변환하고, 이후 11,172자 자동 조합에 사용할 초성·중성·종성 위치형 메타데이터를 생성합니다.

## 2. 유니코드 분해

현대 한글 완성형 범위 `U+AC00–U+D7A3`에 표준 조합 공식을 적용합니다.

- 초성: 19종
- 중성: 21종
- 종성: 없음 포함 28종
- 전체 조합: 19 × 21 × 28 = 11,172음절

모든 현대 한글 음절에 대해 `분해 → 재조합` 결과가 원문과 같은지 전수 테스트합니다.

## 3. 레이아웃 분류

중성을 다음 3종으로 분류하고 받침 유무를 결합해 6개 클래스를 만듭니다.

| 클래스 | 설명 |
|---|---|
| vertical-open | 세로 모음, 받침 없음 |
| vertical-final | 세로 모음, 받침 있음 |
| horizontal-open | 가로 모음, 받침 없음 |
| horizontal-final | 가로 모음, 받침 있음 |
| compound-open | 복합 모음, 받침 없음 |
| compound-final | 복합 모음, 받침 있음 |

## 4. 위치형 데이터

각 음절에는 다음 정보가 저장됩니다.

- 초성·중성·종성 문자와 인덱스
- 레이아웃 클래스
- 역할별 position form ID
- 글리프 잉크 경계
- 역할별 정규화 위치 영역과 픽셀 위치
- 영역 내부 잉크 픽셀 및 전체 글리프 대비 비율

position form ID 예시:

```text
L:ㄱ:vertical:open
V:ㅏ:vertical:open
T:ㄴ:vertical
```

위치 영역은 서로 일부 겹칩니다. 이는 손글씨에서 획이 연결되거나 자모가 영역 경계를 넘는 상황을 보존하기 위한 의도적 설계입니다.

## 5. 폰트 메트릭

- units per em: 1000
- 한글 advance width: 1000
- 목표 수직 영역: y=-40~760
- 목표 최대 가로 윤곽: 880 units
- 실제 윤곽 폭을 기준으로 좌우 여백을 균형 배치
- 한글 Unicode Range bit 56 설정
- Korean Wansung CodePage bit 19 설정

## 6. 산출물 스키마

### `hangul-glyph-manifest.json`

벡터 SVG·윤곽 메타데이터·원본 마스크·위치형 JSON 경로를 음절별로 기록합니다.

### `hangul-position-map.json`

168개 음절의 유니코드 분해, 레이아웃, 위치 영역을 포함합니다.

### `hangul-position-map.csv`

분석 도구에서 바로 열 수 있도록 핵심 필드를 평면화합니다.

## 7. 완료 기준

- 대표 음절 168자 생성 실패 0건
- 모든 음절 분해·재조합 일치
- 모든 역할 위치 영역에 잉크 존재
- 벡터 재래스터 IoU 0.90 이상
- 한글 cmap 168개
- 한글 advance width 위반 0건
- 필수 OpenType 테이블 누락 0건
- 동일 입력 재빌드 SHA-256 일치
